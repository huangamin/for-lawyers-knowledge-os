# Codex 进化治理与法学类比说明书

> 本说明书是学引力 AI 工作体系（Codex / Obsidian 知识库 / Agents / Skills / Tools）规则结构的"法学地图"：用我国法律体系的位阶结构类比说明规则从最高层到执行层的完整层级，并记录每一次规则变动。具备法学背景的使用者，读此一份即可快速知悉体系全貌与演化历史。
>
> **同步义务（固定）**：每次规则发生变化（新增 / 合并 / 修订 / 废止 / 升格 / 降格），必须同步更新本说明书第四节"规则变动记录"，并注明影响的文件与层级。

## ⚖️ 法律严谨点声明（必读）

我国法规范的真实位阶大致为：宪法 → 法律 → 行政法规 → 部门规章 → 地方性法规与规章 → 其他规范性文件。

**特别标注："实施细则"并不是我国统一、固定的法规范等级名称**——"实施细则"可能是行政法规、部门规章或其他规范性文件的具体名称，其位阶因制定主体而异，并非一个独立的法定等级。

因此，本文档中的"宪法—法律—法规/规章—实施细则—案例"是**架构类比**，借用法律位阶的思维方式说明本体系规则的层级关系与效力顺序，**不是**声称现实法律存在这样的严格位阶。类比目的是让规则治理获得"上位规则约束下位规则、修改上位规则优先于堆叠下位规则、规则可废止"的制度刚性。

## 二、规则演化机制

### 2.1 案例 → 规则（禁止把案例直接变规则）

```
Case → Observation → Pattern → Candidate Rule → Conflict Check → Complexity Check → Validation → Rule Promotion
```

- 单次案例 = 观察；
- 重复模式 = 候选规则；
- 稳定规律 = 正式规则。

**账本最小实装（2026-08-15 起）**：规则级元数据以"页面 frontmatter"承载（`review_after` 挂规则载体页自身，如 CLAUDE.md / 本规范 / 本说明书），`usage_count` / `success_rate` 在规则数较少阶段允许留空或标"未采集"，采集时机为 Lint 时人工确认一次；规则数超过约十几条或出现"一页多规则需独立统计"时，再升级为独立注册表（此升级本身遵循"单次案例不升级"）。**Lint 四查负责到期扫描与同步比对，是废止制度的执行机关。**

### 2.2 压缩优先（新增规则前按序检查）

1. 已有规则能否解释？→ 能则不新增；
2. 存在重复规则？→ Merge；
3. 存在冲突规则？→ Amend / Replace；
4. 能否通过修改上位规则解决？→ 改上位，不增下位；
5. 只是一次性特殊情况？→ 保留为 Case，不进规则体系；
6. 新规则是否显著提升执行结果？→ 不能则拒绝新增。

### 2.3 废止 / 合并制度

所有非宪法规则必须允许状态：`ACTIVE → AMENDED / MERGED / DEPRECATED / RETIRED`。规则不能因"曾经有用"而永久存在。元数据模板：

```yaml

level:
domain:
status:
created_at:
last_validated_at:
usage_count:
success_rate:
conflict_count:
exception_count:
complexity_cost:
replacement_candidate:
review_after:
```
